## 分类定义（v2 修订）

| 类别 | 含义 | 处理方式 |
| --- | --- | --- |
| **A 类** | 老师文件已明确，可直接执行 | 无需确认，直接作为设计与编码依据 |
| **B 类** | **项目负责人可以在明确约束下自主选择的技术/实现方案**（不改变业务语义与验收口径） | 列出候选与优缺点，选择后写入 ADR |
| **C 类** | **涉及老师原始要求、业务规则或验收口径不明确，必须向老师确认**的问题 | 保留问题，暂停相关设计；不得由项目方自行决定 |
| **D 类** | 资料之间存在冲突或需进一步核对 | 先核对，不擅自取舍 |

> **v2 归类原则**：凡是「阈值多少」「允许不允许」「怎样算通过」这类影响业务语义或验收判定的问题，一律归 C 类，不伪装成 B 类可选方案。
> **v2 拆分原则**：同一事项若同时包含「技术怎么实现」与「验收怎么判定」，拆成两个编号，分别归 B / C。
> 本阶段**未做任何选择**。B 类候选仅为便于讨论，**不得**被当作已定方案使用。

## 2. B 类：项目负责人可在明确约束下自主选择的技术/实现方案

> 本类**只包含技术或实现层面的选择**，不包含业务规则与验收口径。凡影响业务语义或验收判定的，已移入 C 类（见 §7 调整记录）。

### B-01 字段规范文档的组织形式（依赖 C-02 的答复）

- **原文依据**：任务书 P1 §4 FR-01；P3 §6-3「失物字段规范与库表映射」。
- **性质**：文档组织形式属项目内部编排；**字段语义本身归 C-02，不得在此决定**。
- **候选**：① 一张字段规范表（含 10 列对照）；② 两层结构（物品实体字段表 + 规格控制表）。
- **约束**：无论哪种形式，都必须满足 AC-02「字段规范与库表、接口契约逐项对照一致」。
- **建议**：待 Q-C-02 答复后再定，写入 ADR。

### B-02 缓存键的粒度与组织方式（维度集合由 Q-C-06 决定）

- **原文依据**：任务书 P2 §4 FR-04「键按查询条件维度设计」；P4 §12-3 明确「缓存键粒度」不可交给 AI。
- **性质**：**实现选择**；「必须覆盖哪些维度」属验收口径（Q-C-06）。
- **候选**：
  - 方案① 条件组合键（维度全量拼接）：失效精准；缺点键爆炸、维护成本高。
  - 方案② 单维度粗粒度键：键少；缺点易被判「只删一个粗粒度键」（P4 §12-1 反例）。
  - 方案③ 命名空间 + 版本号：失效只需改版本；缺点读路径多一次取版本。
  - 方案④ 组合键 + 「物品→受影响键」索引集合：精准可批量；缺点索引自身一致性需保证。
- **建议**：在 Q-C-06 答复的维度集合内选定 1 主 1 备，写入 ADR。

### B-03 缓存删除失败窗口内的陈旧数据抑制机制（验收口径见 Q-C-19）

- **原文依据**：任务书 P2 §4 FR-04；P3 AC-04 判定线「出现陈旧列表或超时未修复」；P4 §12-3 将「陈旧窗口可接受范围」列为不可交给 AI。
- **性质**：**技术实现选择**。「窗口内是否允许短暂陈旧、如何判定」属验收口径（**Q-C-19**）。
- **候选**：
  - 方案① 读时二次校验（命中缓存后再按状态过滤）：窗口内即正确；缺点读放大影响 P95。
  - 方案② 维护「已认领集合」（短 TTL），列表渲染时排除：读开销小；缺点该集合也可能写失败。
  - 方案③ 删除失败即标记「键不可信」，读路径降级直查库至补偿完成：窗口内正确；缺点故障期读压力全落库。
  - 方案④ 缩短 TTL（如 10s）：最简单；缺点仅缩小窗口，不满足「期间不得出现」，风险高。
- **建议**：由项目负责人决定并写 ADR；**但「1 分钟内修复」与「期间不得出现」能否同时满足，需 Q-C-19 的答复支持**。

### B-04 认领申请幂等键的技术构成（「同一申请」的业务判定见 C-27；驳回后重申请见 C-20）

- **原文依据**：任务书 P3 AC-05；P2 §5-3。
- **性质**：**仅限技术实现选择**（幂等键以什么字段构成）。「什么情况下两次提交属于同一认领申请」是业务判定，属 **C-27**；「驳回后能否重申请」属业务规则，属 **C-20**。
- **候选**：① 申请人 ID + 物品 ID 唯一约束；② 客户端幂等键（Idempotency-Key）；③ 幂等表（请求指纹 + 时间窗）。
- **风险**：方案①会把「驳回后合法重申请」误判为重复；方案③时间窗取值无原文依据。
- **建议**：待 C-27 与 C-20 明确后选定，写入 ADR。

### B-05 通知去重键的技术构成（触达判定与退避参数见 C-09）

- **原文依据**：任务书 P2 FR-08；P3 AC-07。
- **性质**：**仅限技术实现选择**（去重键以什么字段构成）。「触达」如何度量、退避重试参数均属验收口径（**C-09**），不在本条范围内。
- **候选**：① event_id（生产端 UUID）；② 业务唯一键（申请 ID + 结果类型）；③ 消息体哈希。
- **建议**：选定后写入 ADR；退避参数与触达判定须随 C-09 一并由老师确认。
